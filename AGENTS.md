# AGENTS.md

Conventions for agents building Arbora. The full rules live in [docs/BUILD_STAGES.md](docs/BUILD_STAGES.md) ("Code conventions for the builder agent" and the per-stage gotchas); read them before starting a stage.

Cursor always-on copy of the progress rule: [`.cursor/rules/update-stage-progress.mdc`](.cursor/rules/update-stage-progress.mdc).

## Shipping

Since 2 Nov 2026: work on a branch and open a pull request into `beta`. `beta` is the testing line. `main` is only the stable line: a pull request from `beta` into `main` publishes the next GitHub Release (about 60 billed minutes). Do not open feature pull requests against `main`, and do not push code straight to either branch. Actions minutes are billed, so keep CI runs few:

- **One branch and one PR per logical piece of work** (a stage sub-part, a fix). Commit locally as often as you like; **push when the work is tested locally**, not after every commit. Every push to a ready PR runs CI again.
- **Open the PR as a draft while it is still changing** (drafts skip CI). Mark it ready once, when you expect it to pass. Do not push and mark ready in the same breath (the cancelled draft run takes the ready run with it; see BUILD_STAGES cross-cutting gotchas).
- **Run the checks locally first:** `pnpm typecheck && pnpm lint && pnpm test` before any push with code, and `pnpm e2e` when the change touches the Electron app (needs a display; `xvfb-run -a` on headless Linux). CI is the confirmation, not the place to find failures.
- **Linux only by default.** Add the `ci:all-os` label (macOS costs 10x, Windows 2x) only when the change is platform-specific (paths, shells, keyboard labels, packaging, native modules), once, just before merge, and remove it once that run is green.
- **Merging does not rerun CI;** the PR run is the gate. `main` gets a weekly Linux run (Mondays) and "Run workflow" on demand, and a merge into `main` also starts the release build. If a merge could interact with other merged work, update the branch from `beta` before the final push so the PR run covers the result.
- **Docs-only changes** (`**/*.md`, `docs/**`, `.cursor/**`) skip CI. They still go through a PR, which can be merged without waiting.
- **Releases cost about 60 minutes** (three OSes) and happen by themselves when a pull request merges into `main`. Do not tag a release or run `package.yml` by hand unless you are rebuilding one (docs/RELEASING.md). Merging into `beta` publishes nothing; the in-app Beta channel only gets an `x.y.z-beta.n` when a person runs **Cut a beta** (`release-beta.yml`, also about 60 minutes). Agents do not run it.
- The progress update below goes in the PR with the work, not a follow-up PR. Stage statuses use `In progress (PR #N)` while open and `In progress (PR #N, merged)` / `Done (PR #N)` after merge.

## End of work: update progress

A task is not finished until the phase docs match what you just did. Update them in the **same commit** as the work. Do not leave the tracker for a follow-up commit, and do not skip this because the change was "docs only", a fix, CI, or verification.

1. Read [docs/BUILD_STAGES.md](docs/BUILD_STAGES.md) **Progress** and the current stage checklist, and [docs/PLAN.md](docs/PLAN.md) **Current phase**.
2. Tick finished checklist items. Leave unverified items unchecked (especially Omarchy/Hyprland `arch-ok`).
3. Set the Progress table **Status** and **Notes** for every stage you touched. Notes must be true *now*: the PR and whether it is merged, the CI result (name red jobs and link the run), what is left, what comes next. After the merge, a small docs PR can record "merged" and the final CI run; do not leave "then merge" in the notes.
4. Rewrite **Current phase** in `docs/PLAN.md` so **Now / Next / Blockers** match that table.
5. Append new gotchas to the stage that discovered them. Fill Appendix B cells when you ran a manual agent matrix.

Status values: `Not started`, `In progress` or `In progress (PR #N)` / `In progress (PR #N, merged)`, `Blocked (reason)`, `Done` or `Done (PR #N)`. Work done during the direct-to-main period (30 Oct to 1 Nov 2026) names its commit on `main`; new work names its PR.

Never mark a stage `Done` from CI alone. The definition of done requires `arch-ok` on Omarchy/Hyprland (see BUILD_STAGES "Local testing"). Until then the status stays `In progress` or `Blocked`.

When you finish a stage's code, point the next unstarted stage's Notes at "Next stage" and say what hand-off is ready (hooks, fixtures, settings).

## Commands

- `pnpm install` (postinstall runs `install-electron`; Electron 45 no longer downloads its binary on install)
- `pnpm typecheck && pnpm lint && pnpm test` before every code push; `pnpm e2e` for the Electron smoke tests (needs a display; use `xvfb-run -a` on headless Linux)
- CI minutes are billed. Ship through pull requests into `beta` and keep runs few (see Shipping): drafts while iterating, Linux only, `ci:all-os` (10x and 2x minutes) only for platform-specific changes right before merge. Promote `beta` to `main` only when that line is ready to release.
- `pnpm dev -- /absolute/path/to/project` to launch with a project open
- A checkout instance runs from `apps/desktop/out/`, and `pnpm build:test` rewrites it under a running window. To test without touching it, build into another folder (`out-*/` is ignored) and run Playwright with `ARBORA_E2E_OUT=out-agent`.

## Where things go

- IPC: add channels and events to `packages/shared/src/channels.ts` (zod schemas both ways). Register handlers in `apps/desktop/src/main/index.ts` with `defineHandler`; the renderer calls `window.arbora.invoke(...)` and never imports `electron`.
- Commands: add a `CommandId` and descriptor to `packages/shared/src/commands.ts`, then handle it in the exhaustive `switch` in `apps/desktop/src/renderer/src/commands.ts`. Set `intercept: true` only for chords that must beat the embedded page (mode chords, palette).
- Settings: extend `appSettingsSchema` with a default for every new field; bump `SETTINGS_VERSION` and append a migration when a change is not backwards compatible.
- Panels: lazy-loaded from `apps/desktop/src/renderer/src/panels/` via `React.lazy` in `Workspace.tsx`.
- Browser panel: `apps/desktop/src/main/browser/` (`BrowserService` owns the `WebContentsView`, CDP and screenshots; `BrowserSessions` owns per-project partitions, extensions and the certificate rule). Messages between the page preload (`src/preload/browser.ts`) and main use `packages/shared/src/page-ipc.ts`, not the app's channel registry. Pure CDP/image helpers stay in separate files with unit tests.
- Terminal: `apps/desktop/src/main/terminal/`. `TerminalService` owns the node-pty processes, line buffers and URL detection; `DevServer` handles run/restart; `shell-env.ts` provides the login-shell PATH, and `process-tree.ts` the tree kill. Pure parsing (URLs, shells, dev command, clipboard chords) lives in `packages/shared/src/terminal.ts`. The renderer keeps xterm instances in `panels/terminal/sessions.ts`, outside React, and tab/split state in `terminal-store.ts`.
- Agent panel: `packages/acp-client` holds everything that speaks ACP and has no Electron dependency (`AgentRegistry`, `AgentProcess`, `AcpSession` on the SDK's stable v1 `client()`, `UpdateNormalizer`, path scoping, redaction, the fake agent under `src/testing/`). `apps/desktop/src/main/agent/` has `AgentService` (one session per thread, `.arbora/threads/<id>.json`), `AgentTerminals` (ACP `terminal/*` on `TerminalService`), `attachments.ts` and `ThreadStore`. The renderer keeps thread state in `agent-store.ts` and the UI in `panels/agent/`. Test real agents with `/tmp` scripts that drive the built app through Playwright (see the Stage 3 gotchas); never commit agent credentials or raw ACP logs.
- Agent mode (`Mod+K`): in-page code lives in `packages/browser-bridge` and is imported by the browser preload as `@arbora/browser-bridge/page`: the overlay, descriptors, and `detect.ts`/`components.ts`, which run in the page's main world via `main-world.ts`, so keep them self-contained. Main imports only the DOM-free composer from `@arbora/browser-bridge`. `apps/desktop/src/main/agent-mode/` resolves sources and candidates and sends the prompt; the renderer's state machine is `mode.ts`, and its UI is `panels/agent-mode/`.
- Browser tools for agents (MCP, Stage 5): `packages/mcp-browser-server` is Electron-free. `BrowserMcpServer` (stateless Streamable HTTP on `127.0.0.1`, bearer token), the tools in `tools.ts` with their permission checks in `ToolContext`, CDP-only helpers (`snapshot.ts`, `refs.ts`, `input.ts`, `page.ts`) and the stdio shim (`shim.ts`, built to `out/main/mcp-shim.js`). Main implements its `BrowserToolHost` in `apps/desktop/src/main/mcp/browser-tool-host.ts`, and `AgentService` attaches one server per agent process through the `mcp` option. Add a tool in `tools.ts` with a test in `server.test.ts`, and a step in the fake agent's "tool sweep" when it needs the real page.
- Git (Stage 8): `apps/desktop/src/main/git/` (`GitService` spawns `git`; `github.ts` uses the `gh` CLI). The renderer panel is `panels/GitPanel.tsx`, decorations go through `setGitDecorations` in `files-store.ts`, and the editor gutter is fed from `git-client.ts`.
- Files and editor (Stage 7): `apps/desktop/src/main/workspace/` has `WorkspaceService` (project-scoped fs through `resolveInsideRoot`), `ProjectWatcher` and `IgnoreRules` (chokidar plus `.gitignore`), `FileIndex` and `text-search.ts` (ripgrep with Node fallbacks), and `tooling/` (`ToolingService`; the project's own Prettier and ESLint run in `tooling/worker.ts`, built to `out/main/tooling-worker.js` as a `utilityProcess`, and `tsc` in its own). Loading modules from the user's project goes through `src/main/lazy/project-modules.ts`. The renderer keeps tabs, the tree and diagnostics in `files-store.ts`, and CodeMirror state in `panels/editor/sessions.ts`, outside React. The editor chunk registers an `EditorController`, so `commands.ts` never imports CodeMirror. Open a file with `openFile(path, { at })` and a diff with `openDiff(...)`.
- Distribution and polish (Stage 9): `main/update-service.ts` (electron-updater, channels, manual hints from `packages/shared/src/updates.ts`), `main/attention-service.ts` (desktop notifications, dock badge, taskbar flash, per-window counts), `main/diagnostics.ts` (main log, redacted zip; redaction in `diagnostics-redact.ts`). The renderer's attention state is `attention-store.ts` over the pure reducer in `packages/shared/src/attention.ts`; sounds are synthesized in `sounds.ts`. Agent groups: `AgentGroupStore` in `main/agent/thread-store.ts` (`.arbora/agent-groups.json`) and `threadSections` in `packages/shared/src/agent.ts`. Projects page and switcher: `components/ProjectsHome.tsx`, `components/ProjectSwitcher.tsx`, `projects-store.ts`, `packages/shared/src/projects.ts`. Settings sections live in `panels/settings/*Section.tsx` with shared `controls.tsx`; the onboarding wizard is `panels/onboarding/`. Full-window dialogs set `useApp.overlay` (which hides the browser view) and use `components/Dialog.tsx`. Settings patch schemas must use `patchSchema()` (Zod 4 fills defaults inside `.partial()`). Packaging: `electron-builder.yml`, `build/entitlements.mac.plist`, `.github/workflows/release.yml` (GitHub Releases on this repository; `aur/` is not published); see `docs/RELEASING.md` and, for the website link to the releases page, `docs/WEBSITE_DOWNLOADS.md`.
- Grove (Stage 10): the pure session model is `packages/shared/src/grove.ts` (derived status, auto-start rule, rows, activity, overlaps), and the `when: 'grove'` keybinding context lives in `keybindings.ts`. Main adds `AgentService.stopProcess`, `setArchived` and `waitForSettled`; the orchestration tools are `packages/mcp-browser-server/src/grove-tools.ts` behind the Electron-free `GroveToolHost` (`grove-host.ts`), implemented per calling thread in `apps/desktop/src/main/mcp/grove-tool-host.ts` and attached by `WindowManager.openBrowserTools` for leads only. The renderer keeps selection, launcher and activity state in `grove-store.ts` and derives rows in `grove-model.ts`. Grove is the whole app shell (`layout.workspace` is always `grove`): `App.tsx` renders the lazy `panels/grove/GroveWorkspace.tsx`, one `arbora.shell` panel group with the tree (`GroveSide`), the chat (`SessionPane`, or `DesignPanel` in design mode; `components/ModeSwitch.tsx` in its tab row), `panels/shell/RightColumn.tsx` (the selected project's tabs; the active one is `layout.rightView`, set with `showRightView` in `store.ts`) and `panels/shell/SideColumn.tsx` (Files, Source Control, Search). Selecting a row under another project calls `focusGroveProject`, which opens it on this window (`project.open` with `onThisWindow`). Panel commands go through `withProject` and the shell's `WorkspaceController`. Terminal tab buttons live in `panels/terminal/TerminalTabs.tsx` and editor tab buttons in `components/EditorTabButtons.tsx`, so the shell chunk does not pull in xterm or CodeMirror. The transcript, composer and permission card stay in `panels/agent/`. e2e helpers for the shell (`focusChrome`, `showRight`, `showSide`, `startAgent`) are in `e2e/app.ts`. Settings → Grove is `panels/settings/GroveSection.tsx`; e2e is `e2e/grove.spec.ts` (the fake agent's `grove delegate` drives a lead and a helper).
- Skills and MCP servers (feedback round): `apps/desktop/src/main/skills/` (`SkillLibrary`: the `~/.arbora/skills` library, symlinks into each agent's skills folder, skills.sh search and install; `mcp-import.ts` reads other tools' `mcpServers` files). Paths and parsing live in `packages/shared/src/skills.ts` and `mcp-servers.ts`; `settings.mcpServers` reaches agents through `AgentService`'s `userMcpServers` option. The UI is `panels/settings/SkillsSection.tsx` and `McpSection.tsx`. Tests set `ARBORA_SKILLS_HOME`, `ARBORA_SKILLS_API` and `ARBORA_SKILLS_GIT_BASE`, never the real home.
- Tests: unit tests next to the source as `*.test.ts` (Vitest); e2e in `apps/desktop/e2e/`. Terminal and agent tests spawn ptys, so run them outside Cursor's sandbox. Browser e2e tests start the fixtures themselves (`e2e/servers.ts`) and drive the page via `webContents.executeJavaScript`/`sendInputEvent` from main; find the page's webContents by its `arbora-browser-` partition and skip `devtools:` URLs, which share the session.
